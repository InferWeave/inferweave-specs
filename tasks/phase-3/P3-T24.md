## Outcome
A node executes a GPU swap from persisted intent: drain with a bounded per-model deadline and INSTANCE_DRAINED cancellation, unload, load with every runtime component pinned to the claimed GPU and verified from device memory accounting, warm through the real admission path, and roll back or quarantine on failure, with runtime on-demand loading and eviction disabled.

## Required tests
- request within drain deadline completes before unload
- request past drain deadline receives retryable 503 INSTANCE_DRAINED
- failed load rolls back to the previous deployment and records a start failure
- OOM on load is classified and not retried into the same placement
- executor killed during STARTING resumes from persisted intent
- weights, drafter and projector allocated on the claimed GPU
- request for an unloaded model is refused and evicts nothing

## Operational evidence
Runtime unload force-killed five serving instances after a 10 s stop timeout with no drain (2026-09-02). With only the main-model device set, a drafter and a vision projector allocated on the neighbouring GPU (1.8 GB; 1.1 GB plus 1.1 GB host-mapped) without any error.
