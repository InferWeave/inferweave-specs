## Outcome
Attach to every scope and drift result a stack fingerprint carried in the record's benchmark parameters (so it enters the comparison and series keys with no envelope change): harness id and version, extension versions, the ordered offered tool names with their digest, a digest of the full system prompt, and the chat-template digest observed from the running server rather than declared. A field that was not observed is JSON null, never zero or a guessed value, and marks the result partially attributable.

## Required tests
- a tool-list digest is stable for one list and changes when the order changes
- an unobserved fingerprint field is JSON null and yields a different series key than a present field
- the observed chat-template digest is read from the running server's properties, not from the catalogue
- a missing field never defaults to an empty list, zero or an empty string
