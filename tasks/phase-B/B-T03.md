## Outcome
Refine `state-machines/runtime.md` into the transactional lifecycle
(`DISCOVERED → RESOLVING → PREPARING/DOWNLOADING → RESERVING → STARTING →
LOADING → WARMING → VALIDATING → READY ↔ BUSY/IDLE → DRAINING → UNLOADING →
STOPPED`, with FAILED and cancellation edges) that preserves availability
during swap and expresses `RESERVING`/`DRAINING` only as events to the existing
rebalancer — never a second scheduler.
