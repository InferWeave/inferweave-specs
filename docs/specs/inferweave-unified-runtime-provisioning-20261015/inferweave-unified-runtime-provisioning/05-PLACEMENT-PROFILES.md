# Unified profiles and adaptive placement
Extend EXISTING YAML/JSON profile schema, not a second config system. Proposed fields: execution.preference auto/cpu/gpu/hybrid; allowed backends cuda/rocm/metal/vulkan/cpu; CPU threads/NUMA; GPU offload layers; RAM/VRAM/peak; KV placement; SLO deadlines/TTFT/tokens-per-sec; cost/energy; quantization; context/concurrency; explicit fallback permissions. Align actual names with existing schemas.
Filter by policy, capability, backend compatibility, owner admission, resource reservation, quality, locality and SLO. Rank candidates with measured cold/warm latency, prefill/decode, queue time, throughput, cache reuse and cost. Benchmarks keyed by model digest+quantization+runtime+hardware+context+batch+concurrency+mode; confidence/staleness tracked. Fallback GPU->other GPU->hybrid->CPU only if allowed and SLO achievable; no silent downgrade. Hysteresis prevents thrashing. Structured explanations for placement, rejection, preemption and fallback.
