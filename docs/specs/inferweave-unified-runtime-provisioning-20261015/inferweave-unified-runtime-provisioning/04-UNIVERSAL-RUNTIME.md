# Runtime adapters and model lifecycle
Audit and extend existing adapter interfaces: identity, capabilities, hardware_requirements, validate, prepare, load, unload, health, metrics, cancel, drain, shutdown. Typed modalities: LLM/vision, embedding, rerank, STT, TTS, audio/music, image/edit, video, prediction/classification, RAG/pipelines, scientific/custom jobs. Adapter targets where supported: llama.cpp, vLLM, SGLang, ONNX, PyTorch, TensorRT, TEI, Infinity, faster-whisper/whisper.cpp, Piper/Kokoro, Diffusers, constrained ComfyUI, XGBoost, OCI/Apptainer. Do not assume universal backend compatibility.
Modes: CPU-only, GPU-only, CPU+GPU offload, multi-GPU and multi-node where adapters support. Report exact hardware/runtime capabilities, quantization, supported offload, context, concurrency, streaming and checkpoints. Model lifecycle: discover/license -> fetch/resume -> checksum/signature -> cache -> prepare -> reserve -> load -> warm -> ready -> drain -> unload/GC. Content-addressed artifacts, quotas, shared locks and provenance. Hot swap transactionally: prepare candidate, reserve peak, health-check, route cutover, release old; rollback on failure. Do not promise live state migration unless adapter supports it.
