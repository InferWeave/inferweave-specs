## 0. Headline findings

1. **Accounting is VRAM+KV only.** There is no CPU, host-RAM, NUMA, disk or unified-memory accounting anywhere in the node/gateway capacity path. `CapacityModel::new` rejects `vram_bytes == 0` (`iw-core/src/capacity.rs:259`), and `NodeModelAdvert::validate` rejects it too (`iw-core/src/node_advert.rs:257`), so a CPU-only node cannot be seated or advertise a model without faking VRAM.
2. **Two reservation systems are implemented and neither is the spec-46/50 "rebalancer ledger".** (a) node-local seat/lease admission (`capacity.rs`, `node_admission.rs`), wired; (b) federated provisioning ledger with fencing epoch (`iw-gateway/src/provision_controller.rs`), which is **not wired in any production binary** (only `gateway_e2e.rs` attaches it) and is **not backed by real capacity** (can over-offer; no multi-parent double-spend guard).
3. **Spec 46 GPU-memory reservations, safe-schedulable VRAM, pressure, forecast, placement simulation are wire-types/observation only.** The repo says so itself: `docs/gpu-memory-observation.md:3-5` and `:44-46`.
4. **Many "workstream" modules are dead code in production**: `reservation_policy`, `cache_registry`, `cache_key`, `fed_multi_parent`, `hot_swap`, `runtime_manager`, `effective_profile`, `context_admission` (see section 3). `iw-scheduling` `capacity`/`demand`/`placement`/`sim` are also unconsumed outside the crate; the gateway uses only `state`, `view`, `history`.
5. **Two control loops share the "rebalancer" role**: `iw_core::autoscaler` + `iw-gateway/src/autoscale*.rs` (Slurm fleet; the one the audit/docs call the rebalancer) and `iw_core::adaptive::Controller` + `iw-gateway/src/adaptive.rs`/`runtime_adapter.rs` (instance orchestration, default `shadow`). Plus `retarget`/`repack`/`gpu_swap_policy` inside the first. The "sole authority" claim is by comment convention (`//! ... the rebalancer remains the sole GPU allocation authority`), not enforced by types.

## 4. Decisions and risk

| Area | Decision | Rationale / risk |
|---|---|---|
| Accounting model | **Extend** `iw-core/gpu_memory.rs` wire (spec 46) and `capacity.rs`: add host pools (cpu cores, RAM, NUMA) + a `memoryPool` id so Apple unified memory is one pool; allow zero accelerator pools. | Highest risk: `vram_bytes>0` assumptions in `capacity.rs`, `node_advert.rs`, `adaptive::Worker`, `router.rs` need relaxing without regressing fail-closed behaviour (invariant 36). |
